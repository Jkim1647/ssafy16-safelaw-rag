# 법령 검색 품질 검증

## 검증 환경

- 데이터: 현행법령 381개 조문, 386개 청크 (2026-10-22 이후: 삭제 조문 4개 제외, 377개 조문·382개 청크)
- 임베딩: `text-embedding-3-small`, 1,536차원
- 저장소: Chroma cosine 검색
- 검색: 원문·재작성 질문 순위 결합 + 법률 용어 후보 확장 + 조문 제목 재정렬
- 검색 범위: 사용자가 선택한 법률 도메인으로 제한

## 고정 평가셋과 지표

`data/evaluation/statute_retrieval_cases.json`에 근로계약·부당해고, 전세·임대차 보증금, 상속 질문을 각각 10개씩 저장했다. 각 질문에는 관련성이 있다고 판단한 법령명과 조문 번호를 정답으로 지정했다.

- `Recall@5`: 기대 조문 중 Top-5 안에서 찾은 조문의 비율. 질문별 값을 평균한다.
- `MRR`: 처음 등장한 기대 조문의 순위 역수. Top-5에 없으면 0으로 두고 질문별 값을 평균한다.
- `Hit@5`: 기대 조문을 Top-5에서 하나 이상 찾은 질문의 비율이다. 현재 각 질문에 기대 조문이 하나이므로 Recall@5와 같은 값이다.

평가는 다음 명령으로 재현한다.

```powershell
python scripts/evaluate_statute_retrieval.py
```

질문별 검색어 확장, Top-5 결과, 순위, 점수는 `data/evaluation/statute_retrieval_results.json`에 저장된다. 같은 평가기 버전의 완료 문항은 재사용하므로 중단 후 이어서 실행할 수 있으며, `--no-resume`으로 전부 다시 실행할 수 있다.

## 정량 평가 결과

| 도메인 | 문항 수 | 기준선 Recall@5 | 최종 Recall@5 | 기준선 MRR | 최종 MRR |
|---|---:|---:|---:|---:|---:|
| 근로계약·부당해고 | 10 | 0.700 | 1.000 | 0.650 | 0.808 |
| 전세·임대차 보증금 | 10 | 0.500 | 1.000 | 0.325 | 0.650 |
| 상속 | 10 | 0.700 | 1.000 | 0.600 | 0.883 |
| 전체 | 30 | 0.633 | 1.000 | 0.525 | 0.781 |

기준선 결과는 `data/evaluation/statute_retrieval_baseline.json`, 최종 결과는 `data/evaluation/statute_retrieval_results.json`에 보존한다. 개별 법률 용어의 점수를 모두 누적하면 후보 수는 늘지만 일반적인 용어가 순위를 왜곡했다. 따라서 개별 용어는 후보 수집에 사용하되 가장 강한 용어 신호만 반영하고, 조문 제목과의 정확·부분 일치를 재정렬에 사용했다.

최종 수치는 2026-10-21에 캐시를 사용하지 않고 `--no-resume`으로 다시 측정했다. 생전 증여 질문이 유류분 조문으로 치우치는 실패 사례를 `특별수익자의 상속분` 규칙으로 보정한 뒤 30문항 모두 Top-5 검색에 성공했다.

RRF·MRR의 계산 예시와 문제별 분석은 [`troubleshooting.md`](troubleshooting.md)에 기록한다.

## 개선 전후 사례

`회사에서 카카오톡으로 내일부터 나오지 말라고 했어요`를 원문 하나로만 임베딩했을 때 근로기준법 제27조는 Top-5에 없었다. 다음 검색어 확장 후에는 제27조가 1위로 검색됐다.

```text
해고, 해고 통보, 서면통지, 해고사유, 해고시기, 해고 효력
```

## 알려진 한계

- 검색 결과는 관련 후보 조문이며 사용자 사건에 대한 법률 판단이 아니다.
- LLM이 만든 검색어에 부정확한 용어가 섞일 수 있어 원문·규칙 질의를 함께 사용한다.
- 평가 질문과 정답 조문은 개발자가 작성한 것이므로 데이터 누수와 작성자 편향 가능성이 있다. 별도의 법률 전문가 또는 지도교사 검토가 필요하다.
- 30문항에서 Recall@5가 1.0이어도 실제 사용자 질문 전체에 대한 완전한 검색을 보장하지 않는다. 질문 수와 표현 다양성을 지속해서 늘려야 한다.
- 법령 개정 또는 임베딩 모델 변경 시 전체 색인과 평가 결과를 다시 생성해야 한다.

## 2026-10-22 재평가 (삭제 조문 제외·검색어 변환 모델 변경)

응답 시간을 줄이려고 검색어 변환 기본 모델을 `gpt-5-nano`에서 `gpt-5.4-mini`로 바꾸고, 본문이 "삭제"뿐인 조문 4개를 색인에서 뺀 뒤 같은 30문항으로 다시 측정했다. 결과는 `data/evaluation/statute_retrieval_fast_query.json`이다.

| 도메인 | Recall@5 | MRR |
|---|---:|---:|
| 근로계약·부당해고 | 1.000 | 0.692 (이전 0.808) |
| 전세·임대차 보증금 | 1.000 | 0.675 (이전 0.650) |
| 상속 | 1.000 | 0.853 (이전 0.883) |
| 전체 | 1.000 | 0.740 (이전 0.781) |

순위가 바뀐 문항은 6개다. `gpt-5.4-mini`는 법률 용어를 5~7개로 `gpt-5-nano`(8개)보다 적게 뽑아, 카카오톡 해고 질문(labor-04)의 제27조가 1위에서 2위로, 연장근로 질문(labor-08)이 1위에서 3위로 내려갔다. 반대로 월세 인상 질문(housing-06)은 2위에서 1위로 올랐다. 용어를 6~10개 뽑도록 프롬프트를 보강해 보았지만 MRR 0.708로 더 낮아져 되돌렸다. Recall@5는 그대로 1.000이므로 정답 조문은 모두 근거에 들어간다. 검색 품질을 우선하려면 `GMS_QUERY_MODEL=gpt-5-nano`로 되돌린다.
