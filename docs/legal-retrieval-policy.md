# 법령·판례 검색 정책과 고려사항

## 기본 원칙

SafeLaw는 검색 결과를 법률 판단으로 간주하지 않는다. 법령은 현재 적용되는 일반 규칙의 후보이고, 판례는 특정 사실관계에 대한 법원의 판단 사례다. 답변은 두 문서 유형을 구분하며 승소 확률이나 동일한 결론을 보장하지 않는다.

판례 순위는 다음 두 축을 분리한다.

1. **관련성**: 사용자 질문의 사실관계·쟁점과 얼마나 가까운가
2. **권위**: 전원합의체, 대법원, 항소심, 기타 중 어디에 해당하는가

먼저 의미 검색으로 관련 후보를 제한하고, 그 후보 안에서만 권위 등급에 작은 가점을 준다. 유명한 판례라는 이유만으로 무관한 사건을 상위에 올리지 않는다.

## 현재 반영한 항목

| 고려사항 | 처리 방식 |
|---|---|
| 공식성 | `law.go.kr`, `scourt.go.kr`의 HTTPS 출처만 근거로 허용 |
| 개인정보 | 질문을 외부 모델에 보내기 전에 로컬에서 마스킹하고, 원문은 외부 API·로그·파일·Vector DB에 저장하지 않음(마스킹 비교 화면용으로 현재 Streamlit 세션 메모리에만 일시 보관) |
| 법원급 | 전원합의체·대법원·항소심·기타로 분류해 Chroma 메타데이터에 저장 |
| 판결 정보 | 사건번호, 사건명, 사건종류, 법원, 선고일, 판결유형을 원문 그대로 보존 |
| 법리 연결 | 참조조문과 참조판례를 별도 필드로 보존 |
| 관련성 우선 | 벡터 검색 후보 안에서만 권위 가점을 적용 |
| 법령·판례 분리 | 별도 Chroma 컬렉션에서 검색하고 원시 유사도 점수를 직접 비교하지 않음 |
| 시간 정보 | 법령 시행일·공포일과 판례 선고일을 보존하고 답변에 개정·후속 판례 확인 경고 표시 |
| 근거 검증 | 주장별 근거 번호와 실제 원문 인용문을 검사하고 실패 시 답변 차단 |
| 프롬프트 주입 | 검색 문서는 데이터일 뿐 명령이 아니라는 시스템 규칙 적용 |
| 불확실성 | 법률 자문·승소 가능성 예측을 금지하고 근거 부족 시 답변하지 않음 |
| 감사 가능성 | 수집일, 데이터 건수, SHA-256, 모델명과 평가 결과를 파일로 기록 |

## 자동으로 판단하지 않는 항목

다음 정보는 현재 공개 API 필드만으로 확정할 수 없으므로 추정하지 않는다.

- 판결이 상소로 변경되었는지 또는 현재 확정되었는지
- 후속 판례로 법리가 변경·제한·폐기되었는지
- 판례 선고 당시 조문과 현재 조문이 실질적으로 동일한지
- 특정 판례가 실무·학계에서 반드시 알아야 할 대표 판례인지
- 사용자 사건에 판례가 그대로 적용되는지

`판결유형` 문자열에 “확정”이 포함되더라도 전체 사건의 현재 상태를 독자적으로 보증하는 값으로 사용하지 않는다. 오래된 판례도 중요한 법리를 담을 수 있으므로 최신성만으로 자동 강등하지 않는다.

## 전문가 검수가 필요한 대표 판례 기준

대표 판례 목록은 자동 생성 결과와 분리해 관리해야 한다. 후보 선정 시 다음을 기록한다.

- 사건번호와 공식 원문 URL
- 핵심 쟁점과 법리 한 문장 요약
- 관련 법령과 판례 선고 당시 조문 버전
- 전원합의체 여부와 법원급
- 후속 판례의 유지·변경·제한 여부
- 서비스의 세 도메인에 포함해야 하는 이유
- 검수자, 검수일, 검수 근거

검수되지 않은 자동 수집 판례에는 “대표 판례”, “확립된 법리”, “현재도 유효” 같은 라벨을 붙이지 않는다.

## 남은 검증 과제

- [ ] 도메인별 대표 판례 목록을 법률 전문가 또는 지도교사와 검수
- [ ] 판례 질문을 도메인별 10건 이상 만들어 `Recall@5`, `MRR` 측정
- [ ] 유사 사실관계지만 결론이 다른 어려운 음성 후보를 평가셋에 포함
- [ ] 판례 선고 당시 법령 버전과 현재 조문을 연결
- [ ] 상소·파기·환송·확정 관계를 확인할 수 있는 별도 데이터 확보
- [ ] 후속 판례의 긍정·제한·변경·폐기 관계 검수
- [ ] 데이터 갱신 전후 검색 회귀 테스트
- [ ] 실제 변호사·노무사 검토를 통한 답변 관련성·위험성 평가
