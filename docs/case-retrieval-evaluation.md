# 판례 검색 평가와 동적 보강

## 평가 범위와 기준선

- 평가셋: `data/evaluation/case_retrieval_cases.json`
- 문항 수: 근로·임대차·상속 각 10건, 총 30건
- 정답 단위: Chroma 청크가 아닌 사건번호
- 검수 상태: 개발자 라벨링, 법률 전문가 미검수
- 기준 데이터: 국가법령정보 공동활용 API로 수집한 공개 판례 50건

2026-10-21 결과는 다음과 같다.

| 단계 | Recall@5 | MRR | 오염률@5 |
|---|---:|---:|---:|
| 정적 판례 50건 기준선 | 0.8333 | 0.6250 | 0.6694 |
| 질문 기반 판례 6건·52청크 추가 | 0.8667 | 0.6150 | 0.6644 |
| 쟁점어 게이트·하이브리드 재정렬 | 0.9000 | 0.6806 | 0.5267 |

임대차 분야도 기준선 대비 Recall은 `0.7→0.8`, MRR은 `0.5083→0.5667`, 오염률은 `0.74→0.70`으로 개선됐다. 문서를 추가하기만 했을 때 MRR이 하락한 결과를 통해, 판례 수 확대와 검색 품질 개선은 같은 작업이 아님을 확인했다. 최종 방식은 후보 풀을 넓힌 뒤 사건번호로 조기 중복 제거하고, 사건명·본문·참조조문의 구체 쟁점어가 실제로 확인되는 판례를 우선한다. 구체어 후보가 전혀 없으면 기존 의미 검색으로 폴백한다.

오염률은 상위 고유 사건 중 정답 또는 허용 관련 판례로 라벨링되지 않은 사건의 비율이다. 라벨이 완전하지 않으므로 절대적 법적 관련성 수치가 아닌 개선 전후 비교용이다.

## 발견한 문제

1. 넓은 수집 검색어 탓에 근로 분야에 의료법 사건, 임대차 분야에 증여세 사건 같은 주변 문서가 포함됐다.
2. 한 사건의 여러 청크가 상위를 차지하므로 화면과 평가 모두 사건번호로 중복 제거했다.
3. 근로 12건, 상속 11건으로 문서 풀이 작아 질문 유형을 충분히 덮지 못한다.
4. 현재 50건 안에서 정답을 선정했으므로 미수집 최적 판례를 포함한 전문가 골드셋이 추가로 필요하다.

## 동적 보강 흐름

```text
마스킹된 질문 -> 질문 SHA-256 캐시 확인 -> 법률 검색어 추출(한 번)
-> 처음 보는 질문이면 법률 용어 상위 3개로 판례 목록 API 조회 -> 대법원 공개 판례만 후보화 -> 사건번호 중복 제거
-> 후보 선별 프롬프트(프롬프트2)로 본문을 받을 판례 선택
-> 선택된 판례만 본문 API 조회 -> 쟁점어 확인 -> 새 판례만 섹션 청킹·임베딩·Chroma upsert
-> 원문 질문과 API 키를 제외한 수집 이력과 후보별 선택·탈락 기록 저장
```

### 후보 선별 프롬프트

판례 목록 API는 사건번호·사건명·법원·선고일·판결유형만 준다. `CaseCandidateSelector`는 이 목록을 `P1`~`Pn` 번호로 보여 주고, 법률 검색 문장과 법률 용어에 직접 관련된 판례 번호만 JSON으로 받는다. 본문을 받기 전에 버릴 판례를 정해 본문 API 호출 수를 줄이는 것이 목적이다.

- 사용자 질문은 마스킹본도 보내지 않고 검색어 변환 단계의 법률 검색 문장과 용어만 보낸다.
- 번호 밖의 값과 중복은 버리므로 목록에 없는 판례가 선택될 수 없다.
- 모델 호출이나 응답 해석이 실패하면 `keyword_fallback`으로 전환해 기존처럼 모든 후보의 본문을 받아 쟁점어로만 거른다.
- 선택된 판례도 본문의 판시사항·판결요지·참조조문에 법률 용어가 없으면 색인하지 않는다.

후보마다 다음 결정을 남긴다. 수집 이력 파일에는 사건번호·사건명·법원·선고일·검색어·결정만 저장하고, 선별 이유는 질문 맥락을 담을 수 있어 실행 결과에만 표시한다.

| 결정 | 의미 |
|---|---|
| `indexed` | 선택되어 본문을 받고 색인함 |
| `rejected` | 선별 프롬프트에서 탈락해 본문을 받지 않음 |
| `filtered` | 본문을 받았지만 쟁점어가 없어 색인하지 않음 |
| `duplicate` | 이미 보유한 사건번호 |
| `fetch_failed` | 본문 조회 실패 |

2026-10-22 실제 실행 예: 임대차 계약 갱신 거절 질문에서 목록 후보 8건 중 선별 프롬프트가 상가건물 임대차 묵시적 갱신 판례(2023다307024) 1건만 골라 본문 조회가 8회에서 1회로 줄었다. 양도소득세·가맹사업 등 사건명이 쟁점과 무관한 7건은 `rejected`로 기록됐다. 같은 질문을 다시 실행하면 `cache_hit: true`와 함께 같은 결정 목록을 이력에서 돌려준다.

`data/cache/dynamic_cases.json`(보강한 공개 판례)과 `data/cache/case_collection_history.json`(마스킹 질문의 SHA-256과 검색어만 저장)은 다른 사람이 같은 상태로 검증할 수 있도록 Git에 포함한다. 동일 마스킹 질문은 LLM 검색어가 달라져도 완료 이력을 재사용한다. 외부 API 장애 시에도 기존 정적 검색은 계속 동작한다.

## 재현

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_case_retrieval.py --no-resume
.\.venv\Scripts\python.exe scripts\enrich_case_index.py --category labor --query "계약기간이 끝난 뒤 부당해고 구제를 신청할 수 있나요?"
```

다음에는 실패·고오염 문항을 중심으로 필터를 조정하고, 전문가 검수 골드셋을 만든 뒤 동적 수집 전후를 동일 30문항으로 재평가한다.

최종 상세 결과는 `data/evaluation/case_retrieval_optimized.json`에 보존한다. `review_status`가 명시하듯 평가 정답은 아직 법률 전문가 검수를 받지 않았으며, 임의로 검수 완료 처리하지 않는다.
